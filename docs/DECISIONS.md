# Решения

## 2026-10-09. Движок: Unity 6.3 LTS + URP

Причины и отклонённые варианты — в [SPEC.md](SPEC.md), раздел 3. Версия редактора 6000.3.26f1: для неё есть образ `unityci/editor:ubuntu-6000.3.26f1-android-3.2.2` (проверено по Docker Hub).

## 2026-10-09. Лицензия Unity в CI

GameCI (`unity-builder@v6`, внутри `game-ci/cli`) активирует Personal по логину и паролю: секреты `UNITY_EMAIL` и `UNITY_PASSWORD`.
Секрет `UNITY_LICENSE` с файлом `.ulf` в сборку не передаётся: файл привязан к ноутбуку, и сервер Unity отклоняет его на раннере с ошибкой `TimeStamp validation failed` (запуск 37959440705).

Шаг сборки помечен `continue-on-error`: после успешной сборки GameCI CLI 0.1.72 падает на возврате лицензии (`Serial number unavailable for ULF return`, запуск 37960636141), хотя сама лицензия возвращается. Успех определяет следующий шаг — наличие APK. Убрать обход, когда ошибку исправят в GameCI.

## 2026-10-09. В репозитории нет сцен, префабов и ассетов настроек

Редактор Unity не запускается ни у владельца, ни у разработчика, поэтому YAML-ассеты некому создавать и проверять.
Пустую сцену, ассеты URP и базовые материалы создаёт `BuildScript` при каждой сборке в `Assets/Generated`.
Игровые объекты создаются кодом при запуске.

Материалы создаются при сборке и загружаются через `Resources`, а не через `Shader.Find`: иначе шейдер не попадёт в сборку.

`.meta` файлы создаёт `tools/gen_meta.py` с GUID от пути файла, чтобы кэш `Library` в CI не сбрасывался.

## 2026-10-09. Сборка запускается вручную, APK идёт в GitHub Release

Образ Unity весит около 9 ГБ, сборка долгая, минуты Actions платные. Сборка на каждый push не нужна.
APK кладётся в prerelease, а не в artifacts: релизы не расходуют квоту хранилища Actions.

## 2026-10-09. Подпись

Ключ `~/.config/skyforge-signing/skyforge.keystore` (пароли рядом в `passwords.txt`, в git не попадают), копия в секретах репозитория.
Все сборки подписаны одним ключом, поэтому новая версия ставится поверх старой без потери сохранений.
Идентификатор приложения: `com.skyforge.globalops`. После публикации в Google Play его изменить нельзя.

## 2026-10-09. Тесты запускаются внутри сборки

`BuildScript.RunTests` выполняет EditMode-тесты через `TestRunnerApi` перед сборкой APK; упавший тест останавливает сборку.
Отдельный шаг `unity-test-runner` означал бы второй запуск редактора и вторую активацию лицензии на каждую сборку.
В логе искать строку `[Skyforge] Tests: N passed, M failed`. Строка `TESTS NOT RUN` означает, что тесты не выполнились, и сборку нельзя считать проверенной.

## 2026-10-09. Модель полёта

Горизонтальное движение — наклон вектора тяги плюс линейное сопротивление, подобранное так, что полный наклон даёт ровно `MaxSpeed`.
Ассист задаёт стиком желаемую скорость и сам тормозит и держит точку на ветру; Спорт задаёт стиком наклон, торможения нет.
Симуляция идёт фиксированным шагом 1/120 с, картинка интерполируется, поэтому поведение не зависит от FPS.
Режим Эксперт (ручной газ) отложен: сначала владелец оценивает базовое ощущение полёта.

Земля и вода — аналитическая проверка по той же карте высот, из которой строится меш; деревья — вертикальные цилиндры в сетке. Физический движок Unity не используется.

## 2026-10-09. HUD на uGUI, а не на UI Toolkit

SPEC называл UI Toolkit. Ему нужны ассеты PanelSettings и тема, которые пришлось бы создавать вслепую.
uGUI целиком строится кодом и использует встроенный шрифт. Вернуться к вопросу на этапе 6, когда появятся большие экраны (ангар, глобус).

## 2026-10-09. Ввод через классический Input Manager

Стики читают `Input.touches`, кнопки работают через `StandaloneInputModule`. `BuildScript.UseLegacyInput` выставляет `activeInputHandler = 0`.
