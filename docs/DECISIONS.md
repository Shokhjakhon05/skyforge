# Решения

## 2026-10-09. Движок: Unity 6.3 LTS + URP

Причины и отклонённые варианты — в [SPEC.md](SPEC.md), раздел 3. Версия редактора 6000.3.26f1: для неё есть образ `unityci/editor:ubuntu-6000.3.26f1-android-3.2.2` (проверено по Docker Hub).

## 2026-10-09. Лицензия Unity в CI

GameCI (`unity-builder@v6`, внутри `game-ci/cli`) активирует Personal по логину и паролю: секреты `UNITY_EMAIL` и `UNITY_PASSWORD`.
Секрет `UNITY_LICENSE` с файлом `.ulf` в сборку не передаётся: файл привязан к ноутбуку, и сервер Unity отклоняет его на раннере с ошибкой `TimeStamp validation failed` (запуск 37959440705).

Шаг сборки помечен `continue-on-error`: после успешной сборки GameCI CLI 0.1.72 падает на возврате лицензии (`Serial number unavailable for ULF return`, запуск 37960636141), хотя сама лицензия возвращается. Успех определяет следующий шаг — наличие APK. Убрать обход, когда ошибку исправят в GameCI.

## 2026-10-09. В репозитории нет сцен, префабов и ассетов настроек

Редактор Unity не запускается ни у владельца, ни у разработчика, поэтому YAML-ассеты некому создавать и проверять.
Пустую сцену, ассеты URP и базовые материалы создаёт `BuildScript` при каждой сборке в `Assets/Generated`.
Игровые объекты создаются кодом при запуске.

Материалы создаются при сборке и загружаются через `Resources`, а не через `Shader.Find`: иначе шейдер не попадёт в сборку.

`.meta` файлы создаёт `tools/gen_meta.py` с GUID от пути файла, чтобы кэш `Library` в CI не сбрасывался.

## 2026-10-09. Сборка запускается вручную, APK идёт в GitHub Release

Образ Unity весит около 9 ГБ, сборка долгая, минуты Actions платные. Сборка на каждый push не нужна.
APK кладётся в prerelease, а не в artifacts: релизы не расходуют квоту хранилища Actions.

## 2026-10-09. Подпись

Ключ `~/.config/skyforge-signing/skyforge.keystore` (пароли рядом в `passwords.txt`, в git не попадают), копия в секретах репозитория.
Все сборки подписаны одним ключом, поэтому новая версия ставится поверх старой без потери сохранений.
Идентификатор приложения: `com.skyforge.globalops`. После публикации в Google Play его изменить нельзя.

## 2026-10-09. Тесты запускаются внутри сборки

`BuildScript.RunTests` выполняет EditMode-тесты через `TestRunnerApi` перед сборкой APK; упавший тест останавливает сборку.
Отдельный шаг `unity-test-runner` означал бы второй запуск редактора и вторую активацию лицензии на каждую сборку.
В логе искать строку `[Skyforge] Tests: N passed, M failed`. Строка `TESTS NOT RUN` означает, что тесты не выполнились, и сборку нельзя считать проверенной.

## 2026-10-09. Модель полёта

Горизонтальное движение — наклон вектора тяги плюс линейное сопротивление, подобранное так, что полный наклон даёт ровно `MaxSpeed`.
Ассист задаёт стиком желаемую скорость и сам тормозит и держит точку на ветру; Спорт задаёт стиком наклон, торможения нет.
Симуляция идёт фиксированным шагом 1/120 с, картинка интерполируется, поэтому поведение не зависит от FPS.
Режим Эксперт (ручной газ) отложен: сначала владелец оценивает базовое ощущение полёта.

Земля и вода — аналитическая проверка по той же карте высот, из которой строится меш; деревья — вертикальные цилиндры в сетке. Физический движок Unity не используется.

## 2026-10-09. HUD на uGUI, а не на UI Toolkit

SPEC называл UI Toolkit. Ему нужны ассеты PanelSettings и тема, которые пришлось бы создавать вслепую.
uGUI целиком строится кодом и использует встроенный шрифт. Вернуться к вопросу на этапе 6, когда появятся большие экраны (ангар, глобус).

## 2026-10-09. Ввод через классический Input Manager

Стики читают `Input.touches`, кнопки работают через `StandaloneInputModule`. `BuildScript.UseLegacyInput` выставляет `activeInputHandler = 0`.

## 2026-10-10. Миссии и звёзды

Миссия — данные (`MissionDefinition`: цели по порядку, цель по времени, награда), играет её один класс `MissionRun`.
Типы целей сейчас: взлёт, сканирование точки (зависнуть в зоне), посадка. Этап 4 добавляет остальные типы и выносит миссии в JSON.

Три шкалы: батарея (расход растёт с нагрузкой моторов, 0 % — провал), сигнал (полный до 60 % дальности, дальше линейно падает; 5 секунд без сигнала — провал), корпус (посадка быстрее 2 м/с повреждает, авария — провал).

Звёзды считаются одинаково для любой миссии: 1 — выполнена, +1 — уложился во время, +1 — без повреждений.
Таймер миссии стартует с первым взлётом.

## 2026-10-10. Награды и сохранение

Базовая награда платится за первое прохождение, каждая звезда — в первый раз, когда она получена. Повтор без новых звёзд даёт 10 % базовой награды: переигрывать можно, фармить одну миссию невыгодно.
`MissionOutcome.Granted` не даёт выдать награду за один и тот же результат дважды.

Сохранение — JSON с номером версии в `persistentDataPath/save.json`. Новый файл пишется рядом, читается обратно и только после проверки заменяет старый; предыдущий исправный файл остаётся как `.bak`. Нечитаемый файл без резервной копии откладывается в `.corrupt`, игра начинает с нуля.
Сохранение из более новой версии игры не принимается.

## 2026-10-10. Экономия минут GitHub Actions

Одна сборка на этап: весь этап пишется и проверяется тестами в одном запуске. Сборка идёт около 25 минут; на 2026-10-10 израсходовано примерно 100 минут из 2000 бесплатных в месяц.

## 2026-10-10. Автоскриншоты в сборке

Никто в проекте не видит редактор, а этапы 3–5 владелец проверяет одним разом. Поэтому сборка сама запускает игру в редакторе и сохраняет кадры: `BuildScript.StartScreenshots` входит в play mode, `ShotDirector` расставляет сцены и рендерит камеру вместе с UI в PNG, архив `screenshots.zip` прикладывается к релизу.
Для этого редактор запускается с графикой (`enableGpu`, программный рендер под xvfb) и без `-quit` (`manualExit`); все ветки `BuildScript` сами вызывают `EditorApplication.Exit`.
Кадры сняты программным OpenGL на сервере, а не Vulkan на телефоне: композицию, цвета, вёрстку и грубые ошибки они показывают, производительность и мелкие отличия драйвера — нет.
Скриншоты не блокируют сборку: при ошибке или таймауте (5 минут) APK всё равно собирается. В логе искать `SCREENSHOTS`.

## 2026-10-10. Погода и качество

Погода — данные (`Weather`): свет, небо, туман, цвет моря, осадки и три игровых параметра — ветер с порывами, расход батареи, дальность связи. Всё, что влияет на полёт, показывается в брифинге и на HUD.
Тест следит, чтобы сумма ветра и порывов была меньше максимальной скорости стартового дрона.

Уровни качества меняют масштаб рендера, MSAA, тени, экранные эффекты и плотность осадков. Число каскадов теней и мягкие тени не переключаются: URP вырезает неиспользуемые варианты шейдеров по настройкам ассета на момент сборки. Авто выбирает уровень по объёму памяти и никогда не ставит Ультра.

Вода — собственный шейдер `Skyforge/Water` (непрозрачный, без теней). Если он не скомпилируется, сборка пишет `WATER SHADER BROKEN`, а игра рисует море обычным глянцевым материалом.

## 2026-10-10. Движок миссий

Миссии лежат в `Assets/Skyforge/Resources/Missions/<id>.json` (в Resources, а не в StreamingAssets: на Android StreamingAssets читается только асинхронно через UnityWebRequest). Тексты — в таблице `Loc` по ключам `mission.<id>.title` и `mission.<id>.brief`.

Места в файлах задаются не координатами, а именами якорей острова со смещением: `pad`, `beacon0..2`, `ring0..9`, `poi0..11` (ровные точки в глубине), `coast0..7` (берег), `sea0..3` (вода), `summit`. Остров процедурный, и координаты вслепую не подобрать; якорь гарантирует сухое ровное место без деревьев.

`MissionBuilder` превращает JSON в `MissionDefinition` и возвращает список ошибок. Миссия с ошибками игроку не показывается. Тесты в сборке проверяют каждый файл: структуру, наличие текстов на всех языках, что цели в пределах связи (с учётом погоды) и не внутри препятствий.

Типы целей: takeoff, reach (ворота), scan (зависнуть), observe (держать в кадре), photo (кнопка действия, зум расширяет дальность), follow (держать дистанцию до движущейся цели), find (без маркера, по показаниям сканера), land, strike (сброс боеприпаса), mark (отметить угрозы до подхода колонны), arrive (дождаться колонны).
Обнаружение: радары видят дрон выше своего «пола» в пределах радиуса, акторы — ближе своей дистанции; шкала заполняется за 2,5 с и спадает за 6 с.
Удар: боеприпас падает без тяги, наследует скорость дрона и половину скорости ветра. Красное кольцо на земле показывает точку падения при сбросе прямо сейчас, включая снос ветром; сложность — удержать дрон и набрать минимальную высоту сброса.

Одиннадцать миссий на одном острове: по одной на каждый из десяти шаблонов плюс учебная. Открываются по порядку. Этап 6 добавит регионы и доведёт число до 45.

## 2026-10-10. Отклонения от SPEC на этапе 4

- Груз в доставке не сбрасывается после посадки: дрон остаётся тяжёлым до конца миссии. Упрощение, вернуться при балансе на этапе 5.
- Цели удара в первой версии неподвижны; движущиеся цели и упреждение — в миссиях этапа 6.

## 2026-10-10. Ангар и экономика

Двенадцать дронов в `DroneCatalog`. Отличаются не только скоростью: стелс (`DetectScale`), устойчивость к ветру (`WindFactor`), посадка на воду, независимость батареи от погоды, тепловизор (туман и ночь не сокращают обзор), глушение радаров (`JamScale`), точность удара, грузоподъёмность (`PayloadEase`), зум, минимальная скорость у крыла (не умеет висеть). Тест следит, чтобы у каждого дрона, кроме прототипа, был недостаток относительно стартового или высокая цена.

Улучшения: 5 веток по 5 уровней, каждая что-то даёт и что-то отнимает (`Loadout.Apply`). Цена растёт с уровнем и с ценой дрона; уровни 4 и 5 стоят ещё и детали.
Модули: 6 штук, 2 слота на дрон, покупаются один раз и переставляются между дронами; у каждого тоже есть цена в характеристиках.

Две валюты: кредиты (за миссии) и детали (1 за каждую впервые полученную звезду). Дроны открываются ценой и числом звёзд кампании.
Любая покупка — двумя нажатиями на одну кнопку. Отказ всегда объясняется текстом рядом с кнопкой.

Сохранение — версия 3 (ангар). Версия 2 мигрирует: стартовый дрон и детали за уже полученные звёзды. `Repair` чинит неполные записи дронов, не трогая прогресс.

Вместо модуля «парашют» из SPEC сделано «усиленное шасси»: спасение после аварии потребовало бы переноса дрона из точки столкновения, а это отдельная механика.
Дерево технологий по-прежнему отложено до версии 1.1 (решение SPEC).

## 2026-10-10. Регионы, глобус, кампания

Три региона: Арвелия (зелёный остров), Харад (пустыня), Нордхейм (снежные горы). Регион — это сид острова и биом (`Biome`: высота холмов и хребтов, лес, раскраска земли). Открываются по числу звёзд кампании: 0, 18, 45.
В каждом регионе 15 миссий по одним и тем же 15 схемам; различаются местом на острове, погодой, наградой (множитель 1 / 1,5 / 2,2). Файлы пишет `tools/gen_missions.py` — править таблицы в нём, а не JSON руками.
Последние три миссии региона показываются как этапы крупной операции. Перед финальной — переговоры (`Negotiations`): заплатить 300 кредитов за отключение одного радара, лететь как есть, или лететь в шторм за награду в полтора раза больше. Выбор один раз и навсегда, хранится в сохранении.

Глобус (`GlobeView`) висит на высоте 4 км над островом; камера просто поднимается к нему. Поверхность рисуется шумом: у каждого региона свой континент. Палец вращает глобус, касание маркера выбирает регион.
При смене региона всё региональное (`Region_<id>` в иерархии) уничтожается и строится заново; `Resources.UnloadUnusedAssets` освобождает старые меши и текстуры.

Сохранение — версия 4 (текущий регион, выборы в переговорах).

Отклонения от SPEC: радиопереговоры по ходу миссии не сделаны, сюжет подаётся брифингами, описаниями регионов и переговорами. Спецопераций одна схема на регион (финал), а не три отдельные.

## 2026-10-10. Удержание: ежедневные операции, серия входов, достижения, тайники

Ежедневные операции (`Daily`): три в день, каждая — уже пройденная миссия из открытых регионов с условием (уложиться во время; старт с 70 % батареи; без повреждений). Набор определяется датой устройства и списком пройденных миссий, поэтому одинаков после перезапуска. Платят кредиты и детали сверх обычной награды, один раз за день и слот.
«Сегодня» — дата устройства, но если часы перевели назад, остаётся последняя виденная дата, пока часы её не догонят. Это не защита от взлома, а защита от повторного получения наград переводом часов; в описании игры ничего не обещать.
Серия входов: 7 дней с растущей наградой. Пропуск дня отнимает одну ступень за каждый пропущенный день, а не обнуляет серию. Ничего не сгорает и не отбирается.

Достижения: 40 штук в 13 рядах (миссии, звёзды, дроны, улучшения, километры и т. д.). Каждое следит за числом, которое уже есть в сохранении, поэтому пропустить его нельзя; платит детали один раз.
Тайники: три на регион (вершина, дальний берег, дальняя точка в глубине), собираются подлётом на 9 м, дают детали.

Сохранение — версия 5.

## 2026-10-10. Языки

Английский и русский — две колонки таблицы `Loc`. Каждый следующий язык — отдельный файл `Loc<Код>.cs`, который генерируется из `tools/l10n/<код>.py` командой `python3 tools/l10n/build.py`. Ключ, которого в языке нет, показывается по-английски; тест требует перевода для каждого ключа, где английский и русский тексты различаются, и совпадения подстановок `{0}`.
Сделан узбекский (латиница, апостроф обычный `'`). Перевод выполнен моделью и носителем не вычитан.
Язык выбирается в настройках. Смена языка перезапускает игру из сохранения (`Bootstrap.Restart`), потому что каждый экран уже держит текст на старом языке.
Автоопределение: на Android язык берётся из `java.util.Locale`, потому что в списке `Application.systemLanguage` узбекского нет.

Остальные девять языков из SPEC (испанский, португальский, турецкий, индонезийский, хинди, арабский, немецкий, французский, вьетнамский) не сделаны. Арабский дополнительно требует зеркальной раскладки и шейпинга букв, чего встроенный `Text` не умеет.

## 2026-10-10. Образ Unity и лимит Docker Hub

Раннеры GitHub делят адреса, и Docker Hub иногда отвечает `toomanyrequests` на анонимное скачивание образа `unityci/editor`. Шаг «Pull the Unity image» скачивает образ с Docker Hub и, если тот отказывает, берёт тот же образ через публичное зеркало Google `mirror.gcr.io`; имя скачанного образа передаётся сборщику через `customImage`. Если отказывают оба — шаг падает, и задание нужно перезапустить.

## 2026-10-10. Этап 8: реклама и покупки — сделана только половина, без SDK

Сделано и покрыто тестами:
- `AdRules`: удвоение награды один раз на результат; бесплатный ящик деталей до 3 в день; interstitial только после успеха, не в первой сессии, не раньше 4 пройденных миссий, не чаще раза в 3 минуты, никогда при купленном «Без рекламы».
- `Shop`: каталог из шести товаров и идемпотентная выдача (разовый товар выдаётся один раз, сколько бы раз магазин о нём ни сообщил — это делает безопасным восстановление покупок).
- `IAdsProvider`, `IAnalytics` и места вызова в игре: кнопка удвоения на экране результата, ящик в ежедневных операциях, interstitial перед возвратом в меню, события аналитики.
- Сохранение — версия 6.

Не сделано: SDK Google Mobile Ads, согласие UMP, Google Play Billing, экран магазина. Сейчас провайдер рекламы — `NoAds` («рекламы нет»), поэтому все рекламные кнопки скрыты и игра ведёт себя как без рекламы.

Почему SDK не подключён этой ночью: нативный рекламный SDK нельзя проверить скриншотами в редакторе, а ошибка в его настройке (например, пустой App ID в манифесте) роняет приложение при запуске. Подключать его нужно в сессии, когда владелец может сразу поставить APK на телефон.

Что нужно для подключения: пакет `com.google.ads.mobile` через реестр OpenUPM, ассет `GoogleMobileAdsSettings` с App ID (секрет `ADMOB_APP_ID`), класс-адаптер `IAdsProvider` с тестовыми ID блоков в dev-сборках, форма согласия UMP перед первой загрузкой рекламы; для покупок — пакет Unity IAP, товары в Play Console с теми же id, что в `Shop.Products`, и экран магазина.

## 2026-10-10. Игра стала боевой

Владелец проверил 0.9.2 на телефоне («всё нормально работает») и попросил настоящий экшен с первой минуты: ударные дроны, уничтожение танков, машин, зданий, взрывы, поле боя на карте.

Что изменилось в правилах (`Core/Combat.cs`, это часть `MissionRun`):
- У миссии появились цели (`targets`): вид, место или маршрут, своя или чужая. Вид цели (`TargetKinds`) задаёт прочность, радиус, дальность и урон её оружия. Новый тип задачи `destroy` — уничтожить перечисленные цели.
- У дрона два оружия. Ракеты летят в захваченную цель: захват — ближайшая к носу цель в конусе 32° в пределах `LockRange` при прямой видимости. Бомбы падают по той же баллистике, что и раньше; красное кольцо на земле показывает точку падения. Бетон (бункер, штаб, корабль) от ракет получает 40 % урона — на него нужны бомбы.
- Противник отвечает: вооружённая цель через 1,6 с наведения начинает снимать корпус, пока дрон в её дальности и на прямой видимости. Быстро летящий дрон получает до 55 % меньше. Ракетная батарея видит только дрон выше 40 м над землёй. Корпус 0 — «сбит».
- Посадка на свою площадку пополняет боезапас и меняет батарею. Поэтому в боевых миссиях кончившиеся ракеты — не провал, а потерянное время.
- Бензовоз, склад и бочки при уничтожении взрываются и задевают соседей и сам дрон.
- Миссии с ударными дронами (`strikeDrones`): оружия нет, дрон сам боеприпас. Касание цели или любое падение — взрыв; следующий дрон появляется на площадке. Дронов на один больше, чем целей. В таких миссиях дрон быстрее и умеет пикировать (`DroneSpec.AsStrikeDrone`).
- Колонна, дошедшая до конца маршрута, — провал «цель ушла». Свой пост, который расстреляли рейдеры, — провал «пост потерян».
- Третья звезда в бою — не «без повреждений», а «осталось не меньше половины корпуса»; в миссиях с ударными дронами — «остался запасной дрон».

Кампания: в каждом регионе 15 миссий, 12 из них боевые (штурм, засада на колонну, разведка с ударом по катерам, охота на танки, ударные дроны, подавление ПВО, бомбёжка штаба, оборона поста, налёт на аэродром, ликвидация командира, удар по кораблю, финал) и три мирные (гонка, доставка, скрытный пролёт под радарами). Регионы отличаются составом противника (`tier` в `tools/gen_missions.py`). Старые шаблоны (сканирование, фото, слежка, поиск, сопровождение, шторм) движок по-прежнему умеет, но в кампании их нет.

Карта: `Island.PlaceWar` ставит разрушенные деревни вокруг большинства точек `poi` (руины — препятствия не выше 9,5 м, середина деревни свободна под цели миссий), подбитую технику, воронки, дороги и обгоревшие деревья. Над деревнями стоит дым.

Автопилот в тестах воюет как осторожный игрок: сначала выбивает то, что стреляет, с предельной дальности ракет, бетон бомбит, пустой возвращается на площадку. Все 45 миссий он проходит стартовым дроном.

## 2026-10-10. 3D-модели из открытых источников

Модели техники и дронов взяты с poly.pizza: там лицензия (CC0 или CC-BY 3.0) указана у каждой модели и скачивание идёт без входа. Sketchfab требует аккаунт для скачивания; CGTrader, Free3D и Open3DModel отклонены — у моделей там разные и часто неясные лицензии, для магазина это риск.

Импортёр Unity не используется (редактор никто не открывает, а материалы импортированных моделей зависят от настроек проекта на момент импорта). `tools/gen_models.py` сам читает GLB, приводит оси и размер, красит каждый треугольник одним цветом из палитры модели, упрощает слишком тяжёлые модели и пишет `Resources/Models/<имя>.bytes`; `ModelLibrary` читает эти файлы при запуске. Подвижные части (роторы, башни) хранятся отдельно. Подбитая техника — та же модель с «горелой» палитрой.

Исходники моделей лежат в `tools/models/src`, список авторов — в `docs/CREDITS.md` и в игре (Настройки → Авторы): CC-BY этого требует. При добавлении модели — править таблицу в `gen_models.py`, запускать его с `--preview` и смотреть картинку: нос должен смотреть вверх на виде сверху.

Дома, бункеры, штаб, склад, пехота, гаубица, палатки строятся из примитивов, как и раньше.

## 2026-10-10. Эффекты без прозрачности

Взрывы, огонь и дым — гранёные шарики из пула (`Effects`), которые растут, плывут по ветру и сжимаются в ноль; цвет меняется через `MaterialPropertyBlock`. Прозрачных материалов и новых шейдеров нет: их нельзя проверить без редактора. Из горящих точек острова вживую дымят шесть ближайших к камере, остальные показаны неподвижным столбом.

## 2026-10-10. Локальная проверка без Unity

Сборка в CI идёт 15 минут, поэтому ошибки компиляции и правила игры проверяются на ноутбуке (`tools/check`):
- `check.sh` компилирует весь C# игры против справочных сборок Unity 6000.3.26 (пакет `UnityEngine.Modules` с nuget.bepinex.dev). Для uGUI и URP справочных сборок нет — их заменяют заглушки с сигнатурами.
- `test.sh` запускает EditMode-тесты на .NET против маленькой собственной заглушки `UnityEngine` (векторы, `Mathf`, `JsonUtility`). Шум Перлина там свой, поэтому острова похожи на настоящие, но не совпадают с ними: правила и баланс проверяются, окончательный ответ всё равно даёт прогон тестов внутри сборки.
- `SKYFORGE_TRACE=<id миссии> tools/check/test.sh FullyQualifiedName~Playthrough` печатает полёт автопилота по этой миссии дважды в секунду.

Это компиляция и тесты, а не сборка APK: правило «сборки только в GitHub Actions» не нарушается.
